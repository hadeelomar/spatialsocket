Use Cases

Built for developers building

From gaming to accessibility, SpatialSocket powers immersive audio across every domain.

Gaming
Positional audio where it matters. Attach sound sources to game objects and stream spatial audio server-side. No client-side audio engine required.
Virtual Reality
True binaural immersion for VR and AR environments without client-side processing overhead.
Music Production
HRTF-accurate spatial monitoring and mixing. Preview mixes in 3D before final render.
Video Conferencing
Seat remote participants in virtual 3D space, reducing cognitive load in large calls.
Accessibility
Audio-based spatial navigation for visually impaired users. Precise directional audio cues.
Live Events
Virtual concert stages with per-seat spatial audio. Position performers and audience in 3D.
Education and Broadcast Media
Interactive 3D audio environments for spatial learning and simulation. Spatial audio for podcasts, films, and immersive narratives that wrap your audience inside the story.
API Reference

Simple, event-driven API

Socket.IO events for real-time control, plus HTTP endpoints for file uploads.

Client → Server
EventDirPayloadDescription & Notes
init_audio emit { hrtf_file?: string, use_uploaded?: bool } Initialise the HRTF renderer for this session. Pass hrtf_file (filename inside hrtf_datasets/ on the server, e.g. "p0200.sofa") or set use_uploaded: true to activate the most recently uploaded personalised HRTF for this session. Loading a large SOFA file may take several seconds - the server emits AUDIO_LOADING immediately and AUDIO_INITIALISED when ready. Must be called before any source can be created or audio streamed.
create_source emit { source_id: string, position: {x,y,z} } Register a named 3D audio source at the given position in metres relative to the listener origin. source_id must be unique within the session - attempting to create a duplicate returns CREATE_FAILED. Coordinate system: X = left/right (positive = right), Y = up/down (positive = up), Z = forward/back (positive = toward listener). The renderer is not initialised until init_audio completes.
remove_source emit { source_id: string } Remove a source and free its py3dti resources. Any active stream for this source continues playing from its buffer until the next tick but will stop contributing to the mix afterwards. Safe to call even if no audio is currently streaming from the source.
update_position emit { source_id: string, position: {x,y,z} } Move a source to a new 3D position. The new position is applied on the very next rendered buffer chunk (~23ms at 44.1 kHz / 1024 samples), allowing smooth real-time movement. Can be called at any rate; the HRTF convolution state is preserved across updates so there are no audible discontinuities on position change.
update_listener emit { position: {x,y,z}, orientation: {forward:{x,y,z}, up:{x,y,z}} } Update the listener's position and head orientation in 3D space. forward and up must be unit vectors; they are orthogonalised internally and converted to the quaternion format required by py3dti. Default listener is at origin facing (0, 0, -1) with up (0, 1, 0). Useful for head-tracking in VR/AR applications.
stream_uploaded_file emit { source_id: string, filename: string } Begin streaming a previously uploaded audio file, spatialised from the named source's position. The server decodes the file asynchronously (emits DECODING immediately), then starts emitting file_audio_chunk events at 44.1 kHz / 1024 samples (~23.2 ms) per chunk. The stream loops indefinitely. Multiple sources can stream simultaneously - all are mixed into a single binaural output per chunk. filename must be the secured filename returned by the upload endpoint.
stop_file_stream emit {} Stop all active streams for this session. The server stops emitting file_audio_chunk events and responds with a STREAM_STOPPED status. Any audio already scheduled in the client's Web Audio API buffer will continue to play out. Call before disconnecting to clean up gracefully.
Server → Client
EventDirPayload fieldsDescription
connected on { session_id, sample_rate, buffer_size, message } Emitted immediately on connection. session_id is the Socket.IO SID - use this for all HTTP endpoint URLs. sample_rate is the server's configured output rate (default 44100) and buffer_size is the frame count per chunk (default 1024). Use these values when creating your Web Audio AudioBuffer.
status on { code, message, ...extra } Multiplex status event. code identifies the type (see Status Codes tab). Extra fields vary by code - e.g. AUDIO_INITIALISED includes placeholder_mode: bool indicating whether py3dti loaded successfully or fell back to a simple panning simulation.
file_audio_chunk on { audio_data: string, source_positions: object } Core streaming event. audio_data is a base64-encoded block of IEEE 754 float32 samples in stereo interleaved format (LRLRLR…). Decode with atob() + DataView.getFloat32(), split into left/right channels, and schedule with the Web Audio API. source_positions maps each source_id to { current, total } buffer indices for progress tracking.
error on { message: string, code?: string } Emitted for recoverable errors - e.g. source not found, file not found, decode failure. The session remains active after an error. Distinguish from the disconnect event which signals an unrecoverable connection loss.
Quick Start
const socket = io('http://your-server:5000'); socket.on('connected', ({ session_id, sample_rate, buffer_size }) => { // store session_id for HTTP upload URLs emit('init_audio', { hrtf_file: 'p0200.sofa' }); }); socket.on('status', ({ code, placeholder_mode }) => { if (code === 'AUDIO_INITIALISED') { socket.emit('create_source', { source_id: 'speaker_1', position: { x: 3, y: 0, z: 0 } // 3m to the right }); } if (code === 'SOURCE_CREATED') { // upload audio via HTTP then stream it socket.emit('stream_uploaded_file', { source_id: 'speaker_1', filename: 'track.mp3' }); } }); // receive binaural chunks and schedule via Web Audio let scheduledUntil = 0; socket.on('file_audio_chunk', ({ audio_data }) => { const raw = atob(audio_data); const dv = new DataView(new ArrayBuffer(raw.length)); for (let i = 0; i < raw.length; i++) dv.setUint8(i, raw.charCodeAt(i)); const nSamples = raw.length / 8; // float32 stereo const ab = ctx.createBuffer(2, nSamples, 44100); const L = ab.getChannelData(0), R = ab.getChannelData(1); for (let i = 0; i < nSamples; i++) { L[i] = dv.getFloat32(i * 8, true); R[i] = dv.getFloat32(i * 8 + 4, true); } const src = ctx.createBufferSource(); src.buffer = ab; src.connect(ctx.destination); if (scheduledUntil < ctx.currentTime + 0.3) scheduledUntil = ctx.currentTime + 0.3; src.start(scheduledUntil); scheduledUntil += ab.duration; });
JavaScript
MethodPathDescription
POST /upload/<session_id>/<source_id> Upload an audio file to be streamed from a source. Send as multipart/form-data with field audio_file. Accepted formats: MP3, WAV, M4A, OGG (max 50 MB). Returns JSON with saved_filename - use this exact string (not the original filename) when calling stream_uploaded_file, as the server applies secure_filename() before saving. session_id and source_id must both exist in the session manager before uploading.

Response 200: { "message": "File uploaded successfully", "saved_filename": "speaker_1_track.mp3", "source_id": "speaker_1", "file_info": { "duration_seconds": 214.3, "sample_rate": 44100, "channels": 2 } }
POST /upload_hrtf/<session_id> Upload a personalised SOFA-format HRTF file for this session. Send as multipart/form-data with field hrtf_file. Only .sofa files are accepted. After uploading, call init_audio with use_uploaded: true to activate it. The server always uses the most recently uploaded SOFA file for the session.

Response 200: { "message": "HRTF uploaded successfully", "filename": "my_hrtf.sofa", "session_id": "...", "instruction": "Emit init_audio with use_uploaded=true to activate" }
GET / Health check. Returns server version, active session count, and global performance metrics. No authentication required.

Response 200: { "service": "SpatialSocket API", "version": "0.4.0", "status": "running", "active_sessions": 2 }
GET /files/<session_id> List all audio files uploaded in a session, with metadata (duration, sample rate, channels, estimated buffer count). Useful for building a file picker UI.

All multiplexed through the status event as the code field. Always check d.code rather than d.message - messages are human-readable and may change between server versions.

CodeTriggerMeaning & Extra Fields
AUDIO_LOADING init_audio HRTF file is being loaded from disk and parsed by py3dti. This can take several seconds for large SOFA files. The client should show a loading state and disable the source/stream controls until AUDIO_INITIALISED arrives.
AUDIO_INITIALISED init_audio Renderer ready. Extra fields: hrtf_source (resolved file path), placeholder_mode: bool. If placeholder_mode is true, py3dti is unavailable or the HRTF failed to load - the server falls back to a simple stereo panning simulation. Audio will still stream but without genuine binaural processing.
INIT_FAILED init_audio Initialisation failed - most likely the specified HRTF file does not exist on the server. Check hrtf_source in the payload and verify the file path. The session is still alive; the client can retry init_audio with a corrected filename.
SOURCE_CREATED create_source Source registered successfully. Extra fields: source_id, position: {x,y,z} (server-confirmed coordinates). Use the confirmed position to update your UI rather than assuming the client-side values.
CREATE_FAILED create_source Source could not be created. Common reasons: audio processor not yet initialised, duplicate source_id, or session source limit exceeded (default 16). Extra field: source_id (the ID that failed, for rollback).
DECODING stream_uploaded_file File decoding and resampling started in a background thread. The event thread is unblocked immediately so other WebSocket events can still be processed. Decoding time is proportional to file duration and sample rate conversion complexity. STREAM_READY follows when complete.
STREAM_READY stream_uploaded_file Decode complete, streaming started. Extra fields: source_id, total_buffers (total chunk count for the file), duration_seconds. The session-level streaming task begins emitting file_audio_chunk events at the configured sample rate.
STREAM_STOPPED stop_file_stream All streams for this session have been halted. The background task is terminated cleanly. Any audio already buffered in the client's Web Audio graph will continue to play out - call AudioContext.close() if you want to cut it off immediately.
